৩. Laravel backend

Step 3.1 — API route

adminpanel/routes/api.php
Route::get('/search', [FrontController::class, 'search'])
    ->middleware('throttle:60,1')
    ->name('api.search');

GET কারণ search শুধু data পড়ে। throttle:60,1 মানে একই client প্রতি ১ মিনিটে সর্বোচ্চ ৬০টি request দিতে পারবে। এটি bot/abuse কমায়। সাধারণ customer-এর typing-এ 350ms debounce থাকায় limit সমস্যা হওয়ার কথা নয়।

Step 3.2 — Live suggestion method

FrontController.php
public function search(Request $request): JsonResponse
{
    $term = trim((string) $request->query('q', ''));

    if (mb_strlen($term) < 2) {
        return response()->json(['status' => true, 'products' => []]);
    }

    $products = Product::query()
        ->with([
            'category:id,category_name,category_discount',
            'variants' => fn ($query) => $query->where('status', true)
                ->select('id', 'product_id', 'price', 'stock'),
        ])
        ->where('status', true)
        ->when($request->query('category'), fn ($query, $category) =>
            $query->whereHas('category', fn ($categoryQuery) =>
                $categoryQuery->where('url', $category)))
        ->where(fn ($query) => $this->applySearch($query, $term))
        ->limit(6)
        ->get();

    return response()->json([
        'status' => true,
        'products' => $this->productCards($products, ''),
    ]);
}

status=true শুধু active product আনে। limit(6) dropdown ছোট ও দ্রুত রাখে। with() related data একসাথে আনে, তাই অপ্রয়োজনীয় extra query কমে।

Step 3.3 — Reusable matching query

FrontController.php
private function applySearch($query, string $term): void
{
    $query->where(function ($search) use ($term) {
        $search->where('product_name', 'like', "%{$term}%")
            ->orWhere('product_code', 'like', "%{$term}%")
            ->orWhereHas('brand', fn ($brand) =>
                $brand->where('name', 'like', "%{$term}%"))
            ->orWhereHas('category', fn ($category) =>
                $category->where('category_name', 'like', "%{$term}%"));
    });
}
কেন আলাদা function? Live suggestion, all products এবং category listing—তিন জায়গায় একই matching rule ব্যবহার হয়। Rule বদলাতে তাই শুধু এক জায়গা edit করতে হবে।

৪. Homepage desktop search

HomeHeader.vue — সহজ logic
const config = useRuntimeConfig()
const searchText = ref('')
const selectedCategory = ref('')
const suggestions = ref([])
const searching = ref(false)
const showSuggestions = ref(false)
let searchTimer

watch([searchText, selectedCategory], ([term]) => {
    clearTimeout(searchTimer)
    const query = term.trim()

    if (query.length < 2) {
        suggestions.value = []
        searching.value = false
        return
    }

    searching.value = true
    searchTimer = setTimeout(async () => {
        const params = { q: query }
        if (selectedCategory.value) params.category = selectedCategory.value

        try {
            const response = await $fetch('/search', {
                baseURL: config.public.apiBase,
                query: params
            })
            suggestions.value = response.products ?? []
            showSuggestions.value = true
        } catch {
            suggestions.value = []
        } finally {
            searching.value = false
        }
    }, 350)
})

const submitSearch = () => {
    const params = {}
    const query = searchText.value.trim()
    if (query) params.q = query
    if (selectedCategory.value) params.category = selectedCategory.value
    showSuggestions.value = false
    navigateTo({ path: '/shop', query: params })
}

onBeforeUnmount(() => clearTimeout(searchTimer))

clearTimeout() আগের pending request বাতিল করে। onBeforeUnmount() component বন্ধ হলে timer পরিষ্কার করে। finally success/error দুই ক্ষেত্রেই loading বন্ধ করে।

৭. Shop page-এ সম্পূর্ণ result

shop.vue
const route = useRoute()

const searchTerm = computed(() => {
    const value = Array.isArray(route.query.q)
        ? route.query.q[0]
        : route.query.q

    return value?.toString().trim() ?? ''
})

const { data } = await useAsyncData(
    'shop-products',
    () => $fetch('/products', {
        baseURL: config.public.apiBase,
        query: {
            page: currentPage.value,
            q: searchTerm.value || undefined
        }
    }),
    { watch: [currentPage, searchTerm] }
)

URL /shop?q=t-shirt হলে route.query.q থেকে “t-shirt” পাওয়া যায়। watch: [searchTerm] থাকার কারণে SPA navigation-এ page reload ছাড়াই নতুন result fetch হয়। Backend-এর products() method একই applySearch() ব্যবহার করে এবং প্রতি page-এ ৮টি product দেয়।

দুই endpoint কেন? /search দ্রুত dropdown-এর সর্বোচ্চ ৬টি result। /products হচ্ছে filter, sort ও pagination-সহ পূর্ণ Shop listing।

৯. Security ও performance

  • Search হলো read-only GET; তাই CSRF/XSRF token লাগে না।
  • Eloquent query binding ব্যবহার করায় raw SQL injection-এর ঝুঁকি এড়ানো হয়েছে।
  • ২ অক্ষরের minimum check frontend ও backend—দুই জায়গাতেই আছে।
  • throttle:60,1 abusive request সীমিত করে।
  • limit(6) live dropdown দ্রুত রাখে; পূর্ণ result pagination ব্যবহার করে।
  • শুধু active product এবং active variant নেওয়া হয়।
  • Production-এ nuxt.config.ts-এ hard-coded localhost না রেখে environment variable ব্যবহার করা ভালো।
