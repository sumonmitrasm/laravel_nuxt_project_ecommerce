১. কী সমস্যা দেখা যাচ্ছিল?

PageSpeed Insights-এর মোবাইল রিপোর্টে Largest Contentful Paint: Error! NO_LCP দেখা যাচ্ছিল। একই রিপোর্টে Total Blocking Time-ও NO_LCP error দেখাচ্ছিল। ডেস্কটপে performance score ছিল 98 এবং LCP ছিল প্রায় 0.6 সেকেন্ড।

NO_LCP মানে performance score শূন্য নয়। সেই পরীক্ষায় প্রয়োজনীয় LCP measurement পাওয়া যায়নি, তাই পূর্ণ performance score হিসাব করা যায়নি। মোবাইলে hero ছবি ও শিরোনাম দৃশ্যমান থাকলেও Chrome-এর LCP entry খালি ছিল।

তদন্তে দুটি আলাদা সমস্যা নিশ্চিত হয়েছে: Hot Deals slider-এর অনিচ্ছাকৃত প্রাথমিক scroll এবং Hostinger CDN থেকে পুরোনো CSS আসা। পরবর্তীতে localhost-এর horizontal overflow ও TypeScript error-ও আলাদাভাবে সংশোধন করা হয়েছে।

এই রিপোর্ট পূর্ববর্তী পরীক্ষার পর্যবেক্ষণ ও বর্তমান source code-এর ভিত্তিতে তৈরি। সর্বশেষ deploy-এর পরে সফল PageSpeed রিপোর্ট এই আলোচনায় যাচাই করা হয়নি।

ক. Hot Deals slider নিজে ২ পিক্সেল scroll করছিল

Chrome-এর mobile emulation-এ LCP ও scroll event একসঙ্গে রেকর্ড করা হয়। ছবির download সম্পূর্ণ, heading দৃশ্যমান এবং page visibility ঠিক ছিল। পরীক্ষা করে দেখা যায়, নিচের Hot Deals অংশ বাদ দিলে অথবা তার scroll snapping বন্ধ করলে LCP পাওয়া যায়।

৩.২ — CSS-এর automatic versioning

import { createHash } from 'node:crypto'
import { readFileSync } from 'node:fs'

const stylesheetVersion = createHash('sha256')
  .update(readFileSync(new URL('./public/assets/css/style.css', import.meta.url)))
  .digest('hex')
  .slice(0, 12)

// Inside app.head.link:
{ rel: 'stylesheet', href: `/assets/css/style.css?v=${stylesheetVersion}` }

Build-এর সময় CSS-এর content থেকে version তৈরি হয়। Content বদলালে version বদলায়। পরীক্ষিত একটি build-এর URL ছিল /assets/css/style.css?v=779189e036d1; পরবর্তী build-এ content অনুযায়ী এটি ভিন্ন হতে পারে। Node.js-এর file reading ও hashing build/config পর্যায়ে হয়, browser-এ নয়।

৪. পরে দেখা দেওয়া scrollbar ও editor error

Horizontal overflow-এর আলাদা কারণ

Localhost-এর ডেস্কটপ screenshot-এ নিচের horizontal scrollbar তদন্ত করে দেখা যায়, Hot Deals arrow button viewport-এর বাইরে চলে যাচ্ছিল। Browser-এ button-এর parent ছিল category-api-message এবং তার position ছিল static; প্রত্যাশিত parent ছিল deals-wrap ও position: relative।

Raw server HTML-এ Loading hot deals... ছিল, কিন্তু browser-এ পরে product list ছিল। Shared menu data পাওয়া গেলেও pending আবার true থাকায় markup অসামঞ্জস্য হচ্ছিল। Data থাকলে loading/error placeholder না দেখানোর guard দেওয়া হয়েছে:

const catalogLoading = computed(() => pending.value && !data.value)
const catalogError = computed(() => error.value && !data.value)

Category এবং Hot Deals loading/error condition-এ এই guard এবং Trending empty state-এ catalogLoading ব্যবহার করা হয়েছে। এরপর server HTML-এ deals-wrap পাওয়া যায় এবং browser-এ arrow-এর positioning parent ঠিক থাকে।

Visible vertical scrollbar

প্রথমে শুধু homepage-এর visible page scrollbar লুকানো হয়েছিল। সর্বশেষ অনুরোধে একই নিয়ম সব পেজে প্রয়োগ করতে app.vue-এর global style-এ নেওয়া হয়েছে; index.vue-এর home-page class ও সংশ্লিষ্ট rule সরানো হয়েছে। এটি LCP fix নয়; আলাদা visual preference।

Page scroll বন্ধ করতে overflow-y: hidden দেওয়া হয়নি। Keyboard PageDown দিয়ে নিচে যাওয়া পরীক্ষা করা হয়েছে।

৬. GitHub Actions ও Hostinger-এ কী যাবে?

বিদ্যমান .github/workflows/deploy.yml-এ prod branch-এ push হলে frontend build ও FTP deploy হয়। এই তদন্তে workflow পরিবর্তন করা হয়নি। Frontend-এর .output/public/-এর content যায় server-এর /public_html/-এ। Backend-এর আলাদা SSH step আছে।

  1. প্রয়োজনীয় source পরিবর্তন, package.json ও package-lock.json একসঙ্গে commit করুন।
  2. prod-এ merge হওয়ার পরে GitHub Actions-এর frontend ও backend job সফল হয়েছে কি না দেখুন।
  3. Hostinger hPanel → Websites → সংশ্লিষ্ট website-এর Dashboard → Performance → CDN → Flush cache দিন।
  4. Browser Network panel-এ CSS URL-এ version এবং response body-তে scroll-padding-left: 2px আছে কি না দেখুন। শুধু cache HIT/MISS দেখে সিদ্ধান্ত নয়—সঠিক version ও content পাওয়া গুরুত্বপূর্ণ।
  5. PageSpeed Insights-এ নতুন mobile ও desktop analysis চালান। Mobile LCP যেন সময় দেখায় এবং NO_LCP না থাকে; layout ও scroll-ও যাচাই করুন।

nuxt.config.ts বা node_modules হাতে frontend-এর public_html-এ আপলোড করতে হয় না। Build-এর generated files-ই deploy হয়। GitHub-এর Ubuntu runner notice build machine-এর জন্য; সেটি Hostinger hosting পরিবর্তন বোঝায় না।

Hostinger-এর নির্দেশনা: CDN cache flush ও response header বোঝার পদ্ধতি।

৭. কোন অপ্রয়োজনীয় ফাইল সরানো হয়েছে?
