1. Final সিদ্ধান্ত

এই project-এ final pattern হলো Cache Aside + Model Observer + After-Commit Invalidation + Versioned Filter Cache। Controller cache জানবে না; Model পরিবর্তন হলে Observer automatic কাজ করবে।

Admin / Job / Seeder→Eloquent Model→DB Commit→Observer→Targeted Cache Invalidate
ফল: Admin panel দিয়ে Section, Category, Product বা Brand পরিবর্তন করলে client-কে TTL শেষ হওয়া পর্যন্ত অপেক্ষা করতে হয় না। পরবর্তী API request fresh data পায়।
সৎ সীমাবদ্ধতা: phpMyAdmin/raw SQL এবং mass query Model::where(...)->update() individual model event চালায় না। এগুলোর পরে explicit invalidation বা php artisan cache:clear প্রয়োজন।

2. কোন cache কী কাজে লাগে

3. Menu cache কীভাবে তৈরি হয়

File: app/Http/Controllers/Api/FrontController.php

public function menu(): JsonResponse
{
    $sections = Cache::remember(
        'api.sections-with-categories.v5',
        now()->addHours(6),
        fn () => Section::sections(),
    );

    return response()->json([
        'status' => true,
        'categories' => $sections,
    ]);
}
Cache hit→Cached menu return
Cache miss→DB query→৬ ঘণ্টা cache→Response

৬ ঘণ্টা মানে client-কে ৬ ঘণ্টা অপেক্ষা করতে হবে না। Data change হলে Observer key delete করে; পরবর্তী request আবার DB থেকে fresh menu বানায়।

public function categories(): HasMany
{
    return $this->hasMany(Category::class)
        ->where('parent_id', 0)
        ->where('status', true)
        ->with('subcategories')
        ->withCount('products')
        ->orderBy('position')

4. Shop Brand filter-এর versioned cache

File: app/Support/ShopFilterCache.php

<?php

namespace App\Support;

use Illuminate\Support\Facades\Cache;

final class ShopFilterCache
{
    private const VERSION_KEY = 'api.shop-filter.version';

    public static function version(): int
    {
        return (int) Cache::rememberForever(
            self::VERSION_KEY,
            fn () => 1
        );
    }

    public static function invalidate(): void
    {
        self::version();
        Cache::increment(self::VERSION_KEY);
    }
}

rememberForever() শুধু ছোট version number রাখে। increment() atomic—একই সময়ে দুই update হলে version হারায় না।

Current v7→Product update→Atomic increment→v8

Category-specific brand key

sort($categoryIds);
$scope = $categoryIds === []
    ? 'all'
    : sha1(implode(',', $categoryIds));

$version = ShopFilterCache::version();

return Cache::remember(
    "api.shop-filter.brands.{$scope}.v{$version}",
    now()->addMinutes(10),
    fn () => /* available Brand + product count query */
);

$scope থাকার কারণে Laptop ও T-Shirt-এর cache আলাদা। Version বদলালে পুরোনো key আর read হয় না; তার ১০ মিনিট TTL শেষে cache store থেকে expire হয়।

5. Observer: write-side automation

Observers একবার register করা হয়েছে app/Providers/AppServiceProvider.php-এ:

public function boot(): void
{
    Product::observe(ProductObserver::class);
    Brand::observe(BrandObserver::class);
    Category::observe(CategoryObserver::class);
    Section::observe(SectionObserver::class);

    Paginator::useBootstrap();
}

CategoryObserver — সম্পূর্ণ code

class CategoryObserver implements ShouldHandleEventsAfterCommit
{
    public function saved(Category $category): void
    {
        $this->invalidate();
    }

    public function deleted(Category $category): void
    {
        $this->invalidate();
    }

    private function invalidate(): void
    {
        Cache::forget('api.sections-with-categories.v5');
        Cache::forget('admin.category-form.sections.v3');
        Cache::forget('admin.category-form.parents.v3');
        ShopFilterCache::invalidate();
    }
}

class SectionObserver implements ShouldHandleEventsAfterCommit
{

    {
        $this->invalidate();
    }

    {
        $this->invalidate();

saved() create এবং update—দুটোর পরে চলে। deleted() model delete-এর পরে চলে। তাই Controller-এর প্রতিটি method-এ cache code লিখতে হয় না।
ShouldHandleEventsAfterCommit নিশ্চিত করে transaction সফল হওয়ার পরেই observer কাজ করবে। Rollback হলে cache অকারণে invalidate হবে না।

7. Development rules

এগুলো Observer চালায়

Product::create($data);
$product->update($data);
$product->save();
$product->delete();

এগুলো individual Observer চালায় না

DB::table('products')->where(...)->update([...]);
Product::where(...)->update([...]);
// phpMyAdmin direct edit

Bulk operation দরকার হলে operation শেষে explicitভাবে:

ShopFilterCache::invalidate();
Cache::forget('api.sections-with-categories.v5');
DB-level import বা direct SQL একটি আলাদা maintenance operation। Normal admin CRUD নয়।

8. Backend cache বনাম Nuxt key

useFetch('/menu', {
    baseURL: config.public.apiBase,
    key: 'catalog-menu'
})

Nuxt-এর key: 'catalog-menu' হলো একই page/app-এর async-data identity ও deduplication key। এটি Laravel-এর api.sections-with-categories.v5 database cache নয়। দুই layer-এর নাম ও দায়িত্ব আলাদা।

9. Production configuration

বর্তমান environment:

CACHE_STORE=database

Production deployment-এ নিশ্চিত করতে হবে:

  1. Laravel migrations সফল হয়েছে এবং cache/cache_locks table আছে।
  2. Web processes একই cache store/database ব্যবহার করছে।
  3. Deploy-এর পরে সাধারণ Laravel optimization commands চালানো হয়েছে।
php artisan migrate --force
php artisan optimize:clear
php artisan config:cache
php artisan route:cache
php artisan view:cache

এগুলো deployment commands; প্রতিটি Product add/update-এর পরে চালানোর command নয়।
