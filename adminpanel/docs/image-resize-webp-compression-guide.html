এই document-এ Category, Tag এবং Product image upload করার সময় কীভাবে ছবির aspect ratio ঠিক রেখে resize, WebP conversion ও compression করা হয়েছে তা code-সহ ব্যাখ্যা করা হলো।

১. পুরো কাজের Flow

JPG / PNG / GIF / WebP Upload→Laravel Validation→Intervention Image + GD→Proportional Resize→WebP Quality 84→Public Folder
গুরুত্বপূর্ণ: resize করার সময় crop বা stretch করা হয় না। তাই image ফেটে, লম্বা বা চ্যাপ্টা হয়ে যায় না।

৩. Shared Image Optimizer

app/Support/ImageOptimizer.php

একই code তিন controller-এ copy না করে reusable class তৈরি করা হয়েছে।

<?php

namespace App\Support;

use Illuminate\Http\UploadedFile;
use Illuminate\Support\Str;
use Intervention\Image\Drivers\Gd\Driver as GdDriver;
use Intervention\Image\Format;
use Intervention\Image\ImageManager;

class ImageOptimizer
{
    private ImageManager $manager;

    public function __construct()
    {
        $this->manager = ImageManager::usingDriver(GdDriver::class);
    }

    public function store(
        UploadedFile $file,
        string $relativeDirectory,
        string $prefix,
        int $maxWidth,
        int $maxHeight,
        int $quality = 84,
    ): string {
        $directory = public_path(trim($relativeDirectory, '/\\'));

        if (! is_dir($directory)
            && ! mkdir($directory, 0777, true)
            && ! is_dir($directory)) {
            throw new \RuntimeException('Could not create the image directory.');
        }

        $filename = $prefix.'_'.now()->format('YmdHisv')
            .'_'.Str::random(12).'.webp';

        $image = $this->manager->decodePath($file->getRealPath());

        // Ratio ঠিক রাখে, crop করে না এবং ছোট image বড় করে না।
        $image->scaleDown(width: $maxWidth, height: $maxHeight);

        $image->encodeUsingFormat(Format::WEBP, quality: $quality)
            ->save($directory.DIRECTORY_SEPARATOR.$filename);

        return $filename;
    }

    public function delete(?string $filename, string $relativeDirectory): void
    {
        if (! $filename) {
            return;
        }

        $path = public_path(
            trim($relativeDirectory, '/\\')
            .DIRECTORY_SEPARATOR.basename($filename)
        );

        if (is_file($path)) {
            @unlink($path);
        }
    }
}

৪. Resize-এ Image কেন ফাটে না?

$image->scaleDown(width: $maxWidth, height: $maxHeight);
  • scaleDown() original aspect ratio সংরক্ষণ করে।
  • ছবি maximum box-এর মধ্যে proportionally fit হয়।
  • ছোট image upscale হয় না; ফলে unnecessary blur তৈরি হয় না।
  • কোনো crop না হওয়ায় ছবির অংশ কেটে যায় না।

উদাহরণ: 2400×1600 image-কে 1200×1200 bounding box দিলে output হয় 1200×800। Ratio আগের মতো 3:2 থাকে।

৪.২ Controller-এ __construct() কেন ব্যবহার হয়েছে?

use App\Support\ImageOptimizer;

class ProductController extends Controller
{
    public function __construct(
        private readonly ImageOptimizer $images
    ) {}
}

__construct() হলো PHP class-এর constructor method। Laravel যখন controller তৈরি করে, তখন এই method স্বয়ংক্রিয়ভাবে চলে। এখানে controller জানিয়েছে যে তার কাজ করার জন্য একটি ImageOptimizer object প্রয়োজন।

Laravel object দিল কীভাবে?

Laravel-এর Service Container type hint দেখে ImageOptimizer class-এর object স্বয়ংক্রিয়ভাবে তৈরি করে controller-এ inject করে। একে Dependency Injection বলা হয়।

// নিজে object তৈরি করতে হয়নি:
// $images = new ImageOptimizer();

// Laravel নিজে object তৈরি করে এখানে দিয়ে দেয়:
public function __construct(
    private readonly ImageOptimizer $images
) {}

private readonly-এর অর্থ

অংশকাজ
privateProperty শুধু ওই controller-এর ভিতরে ব্যবহার করা যাবে।
readonlyObject assign হওয়ার পরে property ভুল করে অন্য value দিয়ে পরিবর্তন করা যাবে না।
ImageOptimizerLaravel-কে বলে দেয় কোন class-এর object দরকার।
$imagesController-এর ভিতরে optimizer ব্যবহারের property name।
__construct() ব্যবহার করায় code testable, reusable এবং maintain করা সহজ হয়েছে।

৪.৩ Image-এর সঙ্গে Optimizer Attach হলো কীভাবে?

Optimizer কোনো image-এর সঙ্গে স্থায়ীভাবে attach থাকে না। Form submit হওয়ার পরে controller upload করা file নিয়ে store() method-এ পাঠায়।

Step 1 — Form থেকে image আসে

<input type="file" name="image" accept="image/*">

Step 2 — Controller validation করে

$data = $request->validate([
    'image' => [
        'nullable',
        'image',
        'mimes:jpeg,jpg,png,gif,webp',
        'max:8192',
    ],
]);

Step 3 — Uploaded file optimizer-এ পাঠানো হয়

if ($request->hasFile('image')) {
    $data['image'] = $this->images->store(
        $request->file('image'), // Upload করা temporary file
        'admin/categoryimage',   // Save folder
        'category',              // Filename prefix
        1200,                    // Maximum width
        1200,                    // Maximum height
        84                       // WebP quality
    );
}

$request->file('image') form-এর temporary uploaded file দেয়। $this->images হলো constructor দিয়ে পাওয়া ImageOptimizer object।

Step 4 — Optimizer process করে filename return করে

$image = $this->manager->decodePath($file->getRealPath());
$image->scaleDown(width: 1200, height: 1200);
$image->encodeUsingFormat(Format::WEBP, quality: 84)
    ->save($fullPath);

return $filename;

Step 5 — Database-এ শুধু filename save হয়

// $data['image'] এখন এমন একটি filename:
// category_20260810123456789_aBcDeFgH1234.webp

Category::create($data);

Database-এর image column-এ binary image বা পুরো computer path রাখা হয় না। শুধু generated filename রাখা হয়। Actual optimized file থাকে public folder-এ।

স্থানযা থাকে
Database categories.imagecategory_...webp
Public folderpublic/admin/categoryimage/category_...webp

Step 6 — Browser-এ image দেখানো হয়

asset('admin/categoryimage/' . $category->image)

asset() public folder-এর relative path থেকে browser-এর জন্য সম্পূর্ণ URL তৈরি করে।

http://127.0.0.1:8000/admin/categoryimage/category_...webp

৫. WebP Conversion ও Compression

$image->encodeUsingFormat(Format::WEBP, quality: 84)
    ->save($fullPath);
  • Format::WEBP upload করা JPG/PNG/GIF/WebP-কে WebP output-এ encode করে।
  • নতুন filename সবসময় .webp extension পায়।
  • quality: 84 clarity ও file-size-এর মধ্যে উচ্চমানের balance দেয়।
  • Transparent PNG-এর transparency WebP support করে।
Quality 100 রাখলে file অনেক বড় হতে পারে। খুব কম quality দিলে detail নষ্ট হয়। Product/catalog image-এর জন্য 82–86 সাধারণত পরিষ্কার result দেয়; এই project-এ 84 রাখা হয়েছে।

১০. Upload Validation

'image' => [
    'nullable',
    'image',
    'mimes:jpeg,jpg,png,gif,webp',
    'max:8192',
],

max:8192 মানে সর্বোচ্চ 8MB source file। High-resolution source প্রথমে accept হয়, এরপর resize/compress হয়ে ছোট WebP হিসেবে save হয়। এটি output file 8MB হবে—এমন নয়।

১১. Update ও Delete Lifecycle

if ($request->hasFile('image')) {
    // প্রথমে নতুন optimized image save হয়।
    $data['image'] = $this->storeImage($request->file('image'));

    // সফল হলে আগের image disk থেকে remove হয়।
    if ($record) {
        $this->deleteImage($record->image);
    }
}
  • Edit-এর সময় নতুন image না দিলে existing filename অপরিবর্তিত থাকে।
  • নতুন image upload হলে নতুন optimized file save হয় এবং পুরোনো file delete হয়।
  • Record delete হলে তার image-ও public folder থেকে delete হয়।
  • basename() ব্যবহারে directory traversal থেকে delete path নিরাপদ রাখা হয়েছে।

১২. বাস্তব Verification

Input:  2400 × 1600 JPG
Limit:  1200 × 1200
Output: 1200 × 800 WebP
MIME:   image/webp
Output dimension প্রমাণ করে aspect ratio ঠিক আছে। Output MIME প্রমাণ করে WebP conversion সফল হয়েছে।
Existing images: এই optimization নতুন upload ও image re-upload-এর সময় কাজ করে। আগে থেকে disk/database-এ থাকা পুরোনো image নিজে থেকে পরিবর্তিত হয় না।
